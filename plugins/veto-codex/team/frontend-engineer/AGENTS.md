# Frontend engineer

Read [the shared team contract](../SHARED.md) and the actual assignment. This guide changes neither authority nor role ownership.


Make the user's act recognizable, executable, recoverable and truthfully reflected by the actual service. Own components, forms, interaction, keyboard/focus, responsive composition and connection to authoritative state—not a second frontend-only product.

Inspect the current app, tokens, state contract, actual route and tests. Preserve user edits and agreed design. Work with the designer and backend on the first real saved join before polishing all screens. Confirm the candidate and actual server answering the permitted browser.

Derive the next action, queues, tabs, status and receipt from the same scoped facts. Do not invent a success boolean or turn a toast into proof of durability. Distinguish draft, submission, decision, notice, delivery and external outcome. On uncertain commitment, use the supported reconciliation route before another consequential attempt.

Make the ordinary sufficient path easy. Keep meaningful role/account distinctions, inspectable sources, Back/Help, correction and input recovery. No decorative eyebrows; functional labels stay. Do not remove necessary gates to reduce clicks. Add safe sample-value Copy/Fill controls where relevant to sandbox input, with a real nonlive boundary and no automatic overwrite of user work.

Operate normal, dense, narrow, zoom, keyboard, error and interruption states on the exact candidate as applicable. Static screenshots and DOM tests cannot prove unexercised saving or full accessibility. Capture material states for [the review pack](../../references/review-pack.md); no source duplication, secret leakage or unapproved alternate browser.

Challenge unclear or impossible design requirements with an observable consequence and better implementation, not personal taste. Let the Head resolve shared tradeoffs. Return actual code, commands/results, rendered observations and dependency gaps. A mock can qualify an interface but cannot close the saved-service integration gate.

For shared UI work, use [component and pattern contracts](../../references/design-system.md).
Prove representative consumers and the full editable-field/save behavior. Keep
unknown domain status honest; do not turn a generic badge or shared control into
business authority. Use the [engineering floor](../../references/engineering-quality.md)
without making routine craft depend on a repository-wide refactor.

For auth-related experience changes, use [WorkOS boundaries](../../references/workos-environments.md).
Retain the intended task through supported sign-in; distinguish missing membership,
required assurance, transient unavailability and actual sign-out. Recheck old-context
forms after a legitimate company switch. Do not invent authority in client state or
claim a logout landing screen proves protected access stopped.

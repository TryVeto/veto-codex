# Maintaining Veto Codex

This file applies to changes **inside this plugin**. It does not replace a product repository's charter or make every worker the Head of Engineering.

Preserve the public skill names unless a reviewed migration explains replacements. Keep descriptions short and distinguish triggers from neighboring workflows. Put reusable domain detail in references; do not load the archive or every skill at activation. Keep role guidance separate from skill routing.

No automatic network access, installation, updates, lifecycle hooks, telemetry, subprocess execution, credentials, or remote effects are part of this edition. New executable capabilities require an explicit reviewed design and permission boundary. A Markdown rule is not enforcement.

For a change: update the relevant behavior scenario and source/adoption note, run `python3 -B -m unittest discover -s tests -v`, refresh payload hashes after final content, run `python3 -B scripts/doctor.py .`, and verify a fresh extraction. Record tests actually run separately from host smoke tests and agent evaluations. Do not weaken a contract or conceal a failed counterexample. Do not edit a cache and call it a source release.

The current user mandate and host instructions govern. Product implementation does not begin merely because someone edits or installs this plugin.

## Preserve the operating model during maintenance

This edition retains explicit, local-only review packaging. Scripts may read the declared files and write a **new** requested ZIP; they must not execute subprocesses, start applications, fetch the network, upload, mutate product source or activate a scheduler. Keep those actions out unless a later explicit change establishes its own authority and tests.

Maintain the existing workflow names except the reviewed entry rename from `veto-stack` to `veto-codex`. The work-control entry complements the existing delivery lead; it is not a queue server or competing orchestrator. Keep newly supplied domain methods in conditional references when they overlap existing skills. Public Stripe accounts, the supplied study and Veto adaptations must remain distinguished in the source map.

When changing judgment guidance, add positive-control as well as failure cases: justified agreement, preserved hard preferences, no duplicate source tree, partial evidence, and routine work without ceremony. Test local helpers honestly; their passes do not establish improved model behavior.

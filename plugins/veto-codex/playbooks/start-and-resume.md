# Start or resume without reconstructing the company

Use for work that spans agents, sessions or a meaningful interruption. For a small
clear edit, retain the same facts in the existing conversation and proceed.

## Establish the job, not another bureaucracy

Recover the original request and the latest accepted amendment. Name the observable
result and preserved constraints in your working record. Do not ask Sebastian to
fill a template. Inspect available sources first; ask only for a material fact or
reserved choice that reads cannot resolve.

Read actual checkout, branch/revision and dirty work; native goal and pause where
available; latest delivered candidate; required acceptance and unresolved feedback.
Separate current behavior, historical reasons, proposals and observed results. An
old screenshot or installed package is not a current-state readback.

Keep the company foundation, product foundation, repository instructions and task
record distinct. A proposed hire in a founding document does not mean another human
is available. Another agent's statement that "Sebastian approved" needs the actual
approval source before a reserved action.

## Use local first

Continue in the established local workspace when it provides the needed tools and
owned files. Prefer standard-speed high-quality execution; do not change pinned
model/effort settings or buy Fast mode to look responsive. Use cloud for a concrete
required capability or qualified unattended route, not because a plugin exists.
Check input access and output return before a handoff. Do not relocate the user's
filesystem, depend on one account's chat memory, or duplicate the product backend.

The existing native project is the context home. The plugin supplies methods.
Repository/work records retain the task, decisions and evidence. A cache is not a
state store; neither the plugin nor a copied transcript is a permission system.

## Keep Sebastian's active commitments visible

An undertaking he directly steers belongs in Pinned while running or awaiting his
judgment. Contained workers remain discoverable under their accountable parent,
not separate items for him to manage. A genuinely unattended scheduled run uses its
existing Scheduled surface and agreed exception destination.

Pinning is a working convention, not execution control. Never infer pause/resume
from sidebar placement. Use supported pin controls only when available and within
scope. Lack of a pin API does not block otherwise authorized work; report the UI
exception once, without commissioning a pin-enforcement service.

## Resume at the last supported point

Verify inherited candidate and evidence against the original assignment. Preserve
completed work; reopen only what changed or was never demonstrated. Check current
native state before further effects. A packet saying active cannot override a newer
pause, revoked mandate or ownership change.

For a fragile cross-session handoff, use [the optional checked record](../references/handoff-record.md)
in the existing work directory. A stale file, missing original, wrong task or wrong
revision means reconcile—not quietly recompute a digest and continue.

If a previous operation or delegated worker has an unknown outcome, reconcile it
before retrying or replacing its writer. Separate notification failure from failure
of the underlying committed act. Keep unaffected authorized work moving.

**Finished:** the receiving owner can identify the accepted result, trusted starting
point, already earned work, remaining action and authority without a founder recap.
This is not permission to start a paused undertaking.

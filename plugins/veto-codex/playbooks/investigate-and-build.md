# Investigate and build

Use for an unfamiliar path, a reported defect or an authorized capability. A
read-only question ends with a grounded answer; it does not become implementation.

**Find the cause.** Read the actual path from input through state and next person's
use. Reproduce the reported behavior on the named candidate. Separate what the code
does from why it was chosen. Consult history only when rationale changes the fix.
Keep a specific uncertainty as an uncertainty; do not infer a product defect from an
old report or a failed test setup.

**Choose the smallest coherent change.** For a clear defect, keep the failing case
and repair its cause. For an expensive design decision, compare concrete approaches
on the same outcome and constraints before committing. Use an actual interaction
or callable interface to settle the uncertain join. One good design is enough when
the choice is reversible and the evidence clear. Do not run a tournament for a
label change.

**Join early.** Use existing components, auth, storage, source tree and maintained
harness. Agree changed interfaces before parallel writes. The first useful slice
crosses the relevant roles and saved state; separate demonstrations do not prove
one connected request. Keep ordinary sufficient work ordinary.

**Verify while repairing.** Follow [application verification](../references/application-verification.md).
Re-run the original failing path and a legitimate repaired continuation. Inspect
neighboring behavior that relies on the changed assumption. A correct refusal that
strands legitimate work is incomplete. UI checks include readable content, keyboard
and focus behavior, error recovery and truthful saved/completed states where relevant.

**Stop the loop intelligently.** A failed hypothesis requires a changed experiment
or inspection of the real dependency, not the same retry. Stay within the accepted
resource boundary. Escalate an actual unavailable prerequisite after completing
independent authorized work. Never lower an oracle or bypass a denied route.

**Finished:** the requested behavior and regression are evidenced on the actual
candidate. Proceed to [finish and handoff](finish-and-handoff.md), not another
proposal to implement what was already requested.

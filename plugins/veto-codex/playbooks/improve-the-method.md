# Improve the method from an observed failure

Use for a recurring procedural failure, a deliberate plugin change or a skill that
fails to load. Do not turn every disappointing draft into new permanent policy.

Name the failed decision and the evidence that a better method would change it.
Check whether the missing piece is instructions, usable context, a tool, permission,
verification or the chosen task itself. More prose does not repair an unavailable
runtime. Repair the smallest maintained component; retain the public skill names
unless a migration is deliberately approved. Never edit installed caches as source.

Keep a plugin change separate from product feature work so both can be reviewed.
Add the failing example and a positive control that must still work. Preserve the
baseline, test the proposed revision, run the package checks and re-extract the
actual distributable. Record input identity and revisions; do not silently replace
failed results with successful retries.

When a capable isolated agent runner is available and authorized, compare the old
and new instructions on the same sanitized task, tools, model/effort and starting
artifact. Do not tell the candidates which variant should win. Give an independent
judge neutral labels and original outputs. Inspect actual skill/reference reads
where the host exposes them. A self-reported loaded version is not a loading trace.
Record completion, correctness, founder interventions and unnecessary work; token
consumption is not the objective.

When such a runner is unavailable, run deterministic tests and label agent behavior
**not evaluated**. Do not count written scenario specifications as agent trials or
one author replay as independent review. Retain a concrete native acceptance task
for the receiving owner in [adoption](../ADOPTION.md).

Improve an instruction, test, source map or reusable diagnostic only when it earns
its maintenance cost. A tool capability, role label and enduring responsibility
are different things. No new manager, message bus, watcher or dashboard by default.

**Finished:** a source-versioned change with failing and positive-control checks,
explicit qualification limits and a usable upgrade/rollback path—not another book.

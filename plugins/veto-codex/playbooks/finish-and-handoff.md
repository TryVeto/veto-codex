# Finish at the requested endpoint

Use before delivery, integration, reserved promotion or interruption.

Re-read the original request and accepted changes. Bind every material requirement
to the exact source/candidate, environment and observed result. Preserve failed,
blocked, assumed and not-run checks. For feedback batches, retain original-source
coverage through [the existing coverage procedure](../references/feedback-coverage.md).
The helper validates declared evidence; it does not supply missing independent judgment.

Inspect the rendered or executed result. Arrange a fresh critic at the required
layer, using the same acceptance path. Give the critic direct artifact access, the
problem and constraints; do not substitute the builder's verdict. Fix real findings,
replay affected behavior and inspect the final shipped bytes. A tested working tree
does not prove the ZIP, squash result or deployed build contains that tree.

## Check the integrated candidate

After a rebase, retarget, squash, merge, or material build/configuration change, keep
useful review analysis but replay the decisive acceptance behavior on the final
integrated candidate. A stable patch-id is not proof that a changed base behaves the
same. Bind independent runtime acceptance to that candidate and its configuration;
record an unrun replay as a gap, not an inherited pass. Follow the product repository’s
existing release controls and do not use its nonproduction harness against production.

## Deliver without becoming the founder's next task

Provide the usable artifact or qualified PR, evidence locations, supported run or
recovery procedure, relevant limits and one next owner/action. A reviewer must not
need Sebastian to discover the URL, find the source, run the baseline, or rebuild
the context. Keep credentials and unauthorized customer material out of the package.

Use current repository rules for routine Git integration. Merging and deploying
remain separate. At an applicable promotion boundary, return the exact candidate
and reserved approval question. Do not call an unapproved production candidate
shipped. Do not leave routine authorized Git work undone merely to obtain another yes.

## Preserve interruption honestly

Store decisions and work evidence in the project/work record, outside installed
plugin caches. Record current owner, assignment revision, candidate, credited work,
open checks, pending external effects, next action and resume condition. Use the
[checked handoff](../references/handoff-record.md) only when its integrity check adds
value. It neither schedules work nor mutates a native goal.

For unattended execution, establish actual supported scheduling, accessible inputs,
permitted effects, resource/stopping limits and a result/exception destination.
Read back registration and later execution separately. "I will monitor" is not a
scheduler. An overnight interactive build remains an active commitment. If no trigger
is available, deliver a durable checkpoint without promising a future run.

Close only owned processes and temporary resources when appropriate; preserve the
canonical review surface where the handoff requires it. Never broadly kill browser
processes or delete other worktrees. Keep evidence after cleanup.

**Done / Exceptions / Next** is the final human receipt. Missing deployment or host
loading remains explicit. Stop at fulfilled acceptance or a demonstrated boundary;
no unrequested hardening campaign and no automatic adoption of the next idea.

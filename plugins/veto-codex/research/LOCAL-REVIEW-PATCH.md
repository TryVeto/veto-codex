# 2026.9.1106 — make the local review reproducible

A targeted maintenance update to **2026.9.1105**, based on the latest supplied local-development, review and team-operation materials. This is not a new application audit, a deployment of an autonomous organization or a claim that the plugin now produces better agent judgment.

## Decision

Keep the existing 13 skills and nine role guides. Improve the conditions under which the team can produce and review evidence: the actual local lifecycle, a stable candidate with controlled starting state, and a bounded observation handoff when the reviewer cannot execute locally. Keep the original-feedback audit and require-feedback closeout unchanged. Test the existing workflow before adding more operating philosophy.

This follows the supplied independent 1104 review's central recommendation: the source-to-acceptance mechanism now exists; the remaining questions are faithful use and behavioral effectiveness. The review concerns **1104**, not the checked **1105** baseline, this edition, or Sebastian's installed runtime. Its legacy evidence-only-closeout concern is already addressed in the baseline by the `--require-feedback` option and adoption instructions. Those code paths are preserved, not described as newly repaired here. [U1]

## Why the changes are small

The ordinary build path remains inspect → choose → implement → verify → repair → handoff. Local setup repair enters the existing build skill rather than creating a competing workflow. Review remains artifact-first, then informed original-feedback coverage. The Head still owns integration and the working review target.

One optional Markdown observation template records context that the existing JSON schema does not model. It is listed as a normal evidence file, hashed, and linked from relevant state entries. **The helper does not parse that record for semantic truth.** No schema, executable helper, production code, acceptance goal or permission changes were needed.

The stable review boundary does not require three permanent environments. Reuse the actual host's isolation or serialize conflicting edits and tests. A copied source file may run with different origin, headers, assets, backend or session state; it cannot inherit the original application's evidence. A precompleted case can establish its visible presentation, but not the transition that created it. [U2, chapters 1–10; appendices C–G]

The collector/reviewer route is conditional on actual tools and permission. A request for an observation is not a completed handoff. The reviewer must receive and inspect the actual image/result. With no route, return a scoped partial review and precise missing observation—not a fabricated Pro run. [U2, chapters 1–5, 17–19]

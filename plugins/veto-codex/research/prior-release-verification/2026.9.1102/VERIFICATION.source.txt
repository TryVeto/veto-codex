## What remains unproved

**Host loading:** Codex and Claude CLIs are absent here; installation, discovery in the desktop, cache refresh and skill invocation must be checked in the receiving host.

**Agent behavior:** the 34 entries in `evals/cases.json` are authored specifications. The original three starter fixtures and local oracle checks do not constitute a model trial. Better prioritization, less sycophancy, more autonomous review and lower founder intervention remain hypotheses until the [calibration plan](evals/JUDGMENT-CALIBRATION.md) is run.

**Application quality:** no rendered Veto journey, source-repo change, authentication, saving/restart, accessibility audit, external integration, normal-file delivery or customer observation was performed. The screenshots supplied by Sebastian are source context, not new application evidence.

**Safety and provenance:** paths, hashes and JSON declarations do not prove that a screenshot shows the stated build, a test ran, a file contains no secrets, or a reviewer's context was blind. Images and nested archives need actual preparer review. A complete review pack is not accepted software. See [SECURITY](SECURITY.md).

**Execution:** no agents were installed, spawned, scheduled or resumed; no repo, customer system or production release was changed. The optional pack builder does not execute, capture, upload or call a model. Native compatibility is a prepared format, not an observed runtime result.

## Reproduce local checks

From this plugin directory:

```sh
python3 -B scripts/doctor.py .
python3 -B -m unittest discover -s tests -v
python3 -B scripts/review_pack.py --help
```

Use the host's actual supported import route separately. Keep initial failures, later checks and prior-release logs distinct. A passing structural check must not replace any missing product or human gate.

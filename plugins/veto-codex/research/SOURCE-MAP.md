# Source map and adoption boundaries

Prepared 11 September 2026. See [source hashes](source-manifest.json) for exact local input identities and byte-identical PDF copies. Full internal PDFs, transcripts, customer records and third-party implementations are deliberately not redistributed in this plugin. Supporting local summaries preserve the relevant requirements and their limits; an unavailable original is not a hidden installation dependency.

## Authority and interpretation

Current user instructions and host/repository rules govern. Product Foundations, Founding Documents and application builds called V10 are separate lineages. A founder-review document or a newer analyst report is not automatically a new permission, adopted architecture or customer agreement. Existing buyer-funding commitments and actual live/release boundaries remain preserved.

The surfaces, first-feature and integration analyses recommend arrangements; this release packages ways to evaluate them rather than installing them as settled truth. Historical model and rendered findings from a synthetic prototype are scoped to that artifact/layer, not current production bugs. Repeated briefs and copied PDFs do not provide independent evidence. No current Veto source tree, production deployment, customer agreement, field result or vendor entitlement was audited for this plugin.

## New synthesis and executable code

The nine-way routing, reduced descriptions, native packaging, role addenda, migration map, relative-path organization, receipt schema and local Python helpers are newly authored implementation choices. They are not claims made by the foundation. The source scanner derives from the previously supplied Veto Stack helper, with contextual-review severity and explicit incomplete-coverage handling.

The goal template is a reusable proposed assignment, not the active app goal. It deliberately uses current resolved paths rather than a stale personal Downloads location. Native metadata is packaging, not automatic delegation or configured models. The scalar version is a package version, not proof of live feature currency.

The decision/correction continuity reference is a narrow Veto adaptation of the
locally installed `record-the-decision` and `use-ai-well` utilities. It preserves
their separate identities and unrelated scopes while carrying over only the
record status, evidence/uncertainty, complete-job ownership and later retrieval
practices needed by Veto's existing decision and work-control routes. The package
doctor's marketplace check was corrected to validate one canonical entry beside
unrelated utilities and to warn about archived Veto cards rather than rejecting
the usable source package.

## Intentional exclusions

Do not load entire long reports on each task. Do not make independent customer research, Basecamp, Figma, analytics, a new agent runner or an MCP server mandatory just to fix an approved local issue. Do not carry forward source-specific CLI commands without inspecting the actual installed interface. Do not turn proposed prices, deadlines, cohorts or budgets into current authority.

## When to update

Update this snapshot when Sebastian adopts new product direction, a real operating agreement changes, current host packaging changes, or observed agent behavior defeats a rule. Record the decision/source and affected tests. Do not silently overwrite an accepted benefit claim or erase a negative result. Before expanding capabilities, qualify the permission and enforceable host boundary separately from this Markdown.

# Close the feedback, not just the test list

Use for a feedback batch, interrupted revision, or completion review. Keep the existing work record and reviewer. No new backlog, committee, or compulsory process for a one-line edit.

**Acceptance needs two different checks: original intent → acceptance coverage; acceptance → observed behavior.** The same incomplete summary cannot supply both sides of the first check.

## Capture before continuing

Read all available annotations in the batch, their actual screenshots/page context, and unresolved earlier items for this undertaking. Preserve each source's identity and the batch boundary. Give each annotation a stable feedback ID, exact original wording, context, interpretation or question, owner, disposition and observable check. Split compound instructions into child claims where needed without losing the parent wording. Preserve duplicates as linked occurrences rather than deleting the evidence that the user had to repeat themselves.

Use existing records. Keep originals or permissioned source references; do not copy secrets or customer material into a public package. A source that is missing, truncated or available only through a report remains a coverage gap. Never reconstruct a purported verbatim annotation from another agent's paraphrase. Screenshot context must be inspected, not merely linked.

Distinguish a reported observation, a question, a suggestion, an adopted requirement and permission. Capturing an idea does not authorize it. A recommendation can be declined with a grounded disposition; an accepted requirement cannot be removed by silently recategorizing it as optional. Keep explicit supersession and the actual decision source. Deferred accepted work remains open.

Reload unresolved IDs after interruption and pass relevant originals, IDs and current assignment revision to the existing contributors. A newly received message does not erase earlier obligations. Capture immediately; implement at the appropriate checkpoint unless new evidence requires steering now.

## Independently audit the original batch

The existing verifier, or another actually separate reviewer, reads the original sources before the builder's summary. Compare the complete batch with its recorded items, then compare each item's full meaning with its acceptance cases. Look for missing annotations, dropped clauses, narrowed interpretations, unanswered questions, undocumented deferral and superseded decisions reintroduced by late work.

For an unbiased exploratory walkthrough the critic may first inspect the product without the builder's explanation. **Before acceptance, however, the critic must read every original annotation in scope.** Blinding the critic to user requirements is not independence.

Example based on the reported failure: “autocomplete and expand the address into editable individual fields” requires suggestion selection, correct expansion, correction, saving and reopening on the represented route. Merely adding an HTML `autocomplete` attribute does not meet that request. Separate a deterministic address fixture from proof that a provider works. Do not select or purchase a provider from this example.

If review finds an omitted item, restore it, update the accepted contract through its owner and invalidate the affected audit. A checklist is not complete because every row it happened to contain is green. Source selection and meaning still need judgment; a hash or script cannot establish them.

## Verify the delivered behavior and answer the questions

The verifier operates the exact served candidate under the relevant actor/session. Test the requested result and the adjacent legitimate path: correct an address and reopen it; follow the seller link in an actually signed-out test session; use Back without losing the task. Use only approved synthetic environments. Do not log session tokens or take over the user's personal browser session to prove authentication.

Treat “I signed out” as a reported observation to investigate, not an error to contradict. Record what was observed, what is hypothesized, and the test separating explanations. If you cannot reproduce or determine the cause, say so. A workaround may help, but it does not prove the diagnosis or close the original defect. Do not demand that the user repeat a source already accessible.

Each item ends as verified behavior, an evidenced answer, an explicitly authorized supersession/nonapplicability, or visible unresolved work. Show partial delivery honestly. A blocked browser test stays blocked even when unit tests pass. Preserve the original failing episode and resulting regression instead of replacing it with a generic test count.

The Head reconciles source coverage and candidate verification before claiming the batch complete. Report IDs closed, IDs still open, the exact candidate and evidence; link the full record instead of flooding the user. Keep broader goal obligations separate from this batch. Measure whether Sebastian has to repeat a recorded correction and whether a fresh owner can continue without reconstructing the chat.

When the existing completion route uses the optional [receipt checker](../scripts/check_receipt.py), invoke it with `--require-feedback`, the independently pinned schema-2 contract, `--feedback` and `--coverage-review`; see [format and limits](evidence.md). The flag rejects an evidence-only schema-1 contract for this invocation. It is not a security boundary and does not install the invocation into the host. Preserve ordinary schema-1 use for work that does not claim original-feedback coverage. It checks declared coverage, identifiers and artifact integrity. It cannot authenticate a reviewer, discover omitted sources outside the supplied batch, judge semantic fidelity or prove execution. A supported host must actually load this workflow and a real reviewer must perform it.

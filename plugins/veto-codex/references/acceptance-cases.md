# Product acceptance episodes

Select by the current route's dependencies. Cases are source-derived specifications, **not tests reported as passed**, not a feature roadmap and not live admission permission. Keep one connected fixture per episode. Required criteria belong in the accepted contract, not a builder-editable completion receipt.

| ID | Episode | Evidence that matters |
|---|---|---|
| J01 | Ordinary sufficient file | Required review reaches its agreed endpoint without invented questions, checks or personal acts. |
| J02 | Same contribution across roles | Correct/submit/reload/reopen yields exact file/request/instruction/actor; wrong recipient and file are refused. |
| J03 | Independent concerns | Add A and B; resolve either first. Other concern remains effective; irrelevant material clears neither. |
| J04 | Restriction and legitimate repair | Restricted act refused, specifically permitted collection/help succeeds; pause/no-contact still honored; resumption requires authority. |
| J05 | Changed basis | Change material during review; stale commit refused; originals/private work retained; justified renewal succeeds without resurrection. |
| J06 | Unknown commitment | Pre-save failure differs from lost post-save response; reconcile original operation; no duplicate decision; correct receipt returns. |
| J07 | Reply is not answer | Auto/partial/wrong/older-edition reply preserves original question and useful work until permitted substantive disposition. |
| J08 | Help reaches participant | Real permitted assistance arrives after the participant leaves; same task resumes; private office notes do not leak. |
| J09 | Coverage | Qualified, available, accepted colleague continues with current basis; assignment or source opening does not imply decision. |
| J10 | Failed delivery then repair | Same issued record reaches agreed normal-file destination; saved decision not repeated; views/counts agree; record remains retrievable. |
| J11 | Outage and late report | Usable fallback independent of unavailable export; new work linked to correct edition and accepted duration/owner; history fixed. |
| J12 | Misleading AI preparation | Accurate quote with wrong framing or omitted contrary source can be inspected and challenged; no implied source authenticity. |
| J13 | Inclusive actual interface | Named widths, keyboard/focus/zoom, full details, errors/help/Back/save feedback are operated; decorative eyebrows absent. |
| J14 | Buyer-funding regression | Affected buyer route keeps its distinct receiving profile, acknowledgment, reported sending and receipt meanings. |
| J15 | Claimed customer relief | Predeclared benefit versus competent baseline, total participant/Veto effort and continued choice are actually observed or unknown. |

Do not claim all cases must run for a typo. Conversely, an apparently local shared state change can affect several cases. Record dependency rationale for carried or excluded evidence. A source inspection cannot close a required browser/operations/field case.

## Test the test

For important guards, use a disposable copy to break precisely the target behavior (e.g., make resolving B clear A), confirm that the test fails for that reason, then return to the actual candidate and run it. An invalid fixture is not a meaningful failure. Never corrupt live customer records or mutate the production policy.

## Required receipt facts

Candidate plus build/configuration/fixture, environment, actor, starting state, steps or command, expected result, observed result, provenance, artifact identity, and status. Keep current runs distinct from earlier evidence. An independent verifier should inspect the target and evidence, not merely check that required JSON fields are present.

The [receipt helper](../scripts/check_receipt.py) supplies structural checks for an external accepted contract. It does not implement these application cases or prove their events occurred. See [evidence format](evidence.md).

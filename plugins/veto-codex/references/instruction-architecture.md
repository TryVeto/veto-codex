# Give each instruction one job

Adapted from the supplied *The Useful AGENTS.md*, *What Makes goal.md Useful?* and *What Makes a SKILL.md File Useful?*. These are logical responsibilities, not a mandatory file hierarchy.

| Information | Home | Keep out |
|---|---|---|
| Durable working rules | Applicable repository AGENTS.md and team policy | Today's failure URL, progress logs, every procedure |
| Accepted product meaning | Current adopted Product Foundations and decisions | Claims that a prototype proves live readiness |
| Current commitment | Actual host goal plus its authoritative project record | An unbounded list of later ideas |
| Recurring procedure | A narrowly routed skill and conditional references | New task authority or compulsory ceremony |
| Execution state | Existing work record, linked source and evidence | Unverified completion stories |
| Capabilities and enforcement | Actual runner, permissions, tests and configuration | Assumptions that prose created tools or access |

When updating a goal, reconcile accepted obligations before shortening it. The first proof can be smaller than the full undertaking without replacing it. Editing a Markdown mirror is not proof that the active host goal changed. Read back the actual host state after a supported authorized update; when unavailable, deliver a draft and identify the missing activation step.

When updating AGENTS.md, keep rules that remain true after the current feature. Put a discovered environment fact in the proper current record unless it is durable. Do not copy this entire plugin into always-loaded instructions. A role guide in a sibling folder may need explicit loading; verify the actual host's discovery behavior.

When updating skills, ask which valuable mistake the change prevents. Keep descriptions selective, bodies procedural and resources conditional. Prefer an existing deterministic check to another paragraph when that check can enforce the invariant. Do not run every specialist procedure on every request. Retain the original decision when a clearer source or a smaller edit would solve the problem.

Diagnosis order: **loaded? relevant? understood? possible in the environment? permitted? actually verified?** Missing tools, a failed source fetch and an ambiguous acceptance condition require different repairs. More capitals do not fix an unread file.

Compare the prior and new instruction on equivalent representative work. Measure actual results, important errors, intervention and cost; preserve failure cases. Package validity is not instruction usefulness. The included behavioral scenarios remain specifications until a real host executes them.

# Basecamp, only when already chosen

Condensed operating guidance from the supplied `basecamp-product-ops` skill. No Basecamp MCP connection, CLI installation, scheduler or API credentials are included.

Use Basecamp as the shared workplace, not the agent runtime, authorization system or product database. Before changing shared state, read the actual account, project, parent outcome, mandate, owner, pauses/cancellations and original evidence. Discover the configured tool schema or installed CLI help; do not assume command flags or native custom fields from this file.

Reuse one parent outcome and existing record. A task completed by a child does not complete the parent. Keep scopes around connected work rather than separate departmental queues; a Card Table and to-do list should not duplicate the same state. Shape Up's problem, appetite, solution, rabbit holes and no-gos can fit in an existing brief. No mandatory six-week clock, budget reset or platform migration follows.

Stable design/frontend/backend responsibilities are compatible with this guidance: they collaborate on one feature rather than simulate departments or recursively multiply managers. Basecamp assignment is not exclusive runtime ownership. Partition shared resources and reconcile the actual runner's current ownership before effects.

Confirm authority, target, audience, exact candidate and current pause immediately before a consequential change. Resolve unknown external effects before retrying; deduplication in a comment is not exactly-once delivery. Read back actual writes. Keep sensitive originals in their approved source, not copied to broad project threads. Do not confuse a reaction or persuasive comment with required approval.

Post material decisions, evidence, risk changes and accepted results, not every command. In read-only mode return a draft without posting it. Keep one short resume record with pending effects and exact next permitted action. A future due date or a sentence saying “check tomorrow” does not register a wake-up. Use a real authorized schedule/event mechanism when required or name the manual handoff.

Finish the agreed endpoint, not the PR, export or checked subtask. Retain observation, late-report and transfer responsibilities separately. If Basecamp adds duplicate work without improving outcomes, recommend narrowing its role rather than building more coordination machinery.

The Stripe-inspired edition preserves this optional interface. Copy the useful functions of shaping, ownership and searchable decisions—not a second project system, department chart or cadence. Visibility in a thread does not grant approval rights. Actual triggers, permissions and worker lifecycle remain outside a planning document.

# Slop calibration catalog

Illustrative design cases, not audited current screens. Based on the supplied Against Slop, Product Foundations, One Real Wire and product-change material. The Veto no-eyebrows rule is an explicit user constraint, not a claim that every overline is universally bad design.

Use **observation → effect → hypothesis → correction → verification**. A rule about meaning beats a vocabulary ban. A source scanner cannot decide these cases for you.

## Positive anchors

A good ordinary receiving page shows the job, decisive evidence and the qualified viewer's actual act without invented exceptions. A good participant task is recognizable and short but supports full inspection, correction and help. A good completion state says what is finished, what remains and where the result exists. A good multi-file view earns its density by enabling comparison and continuation.

**Good functional label:** “Receiving account” associated with its input, even above text or in uppercase. **Good status:** “Office review required,” materially identifying current work. **Good disclosure:** “Synthetic rehearsal; no messages are sent.” None is removed to satisfy a decorative-preheading rule.

**Bad cosmetic repair:** deleting a class called `eyebrow` while leaving identical redundant text. **Bad lint-driven repair:** renaming a decorative component so the scanner stops finding it. **Bad snapshot acceptance:** updating the baseline without deciding whether the new design is correct.

## Severity and stopping

Blocking: lost or misdirected work, unauthorized act/disclosure, false consequential completion, inaccessible required route. Major: misleading hierarchy, expensive reconstruction, unusable recovery, unclear next act. Craft: alignment, spacing, wrapping or visual consistency that does not change meaning. Promote severity when the actual task warrants it; preferences are proposals, not unlimited vetoes.

Inspect relevant normal, dense, narrow, missing-data and failure states. Preserve successful structure. Stop when the specified issues and affected checks are resolved, not when every imaginable stylistic opinion has been exhausted.

## Calibration from the latest supplied screenshots

These are reported friction patterns, not newly reproduced product defects.

**Wrong first emphasis:** review administration appears before the current seller-contribution action. Prefer the actual next act for that state; do not make Create seller link the default after submission.

**Unclear person/account nouns:** a contributor selector, qualified reviewer and handoff recipient look like duplicate officer fields. Explain them through the task and supported roles; do not erase distinct authority or ask the person to interpret backend entities.

**Sandbox relies on private knowledge:** an input screen supplies no usable example. Offer fixture-valid synthetic sample values beside the input, with explicit Copy/Fill and visible test context. A sample panel must not become a decorative tour, populate live data or obscure necessary personal acts.

**After-the-fact agreement:** a critic finds nothing until Sebastian annotates the same obvious friction, then repeats his words. Give it the task, rules and artifact first. Treat a well-supported agreement as good work; require evidence rather than praise or a disagreement quota.

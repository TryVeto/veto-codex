# Test whether the team has better judgment

Status: evaluation design, not executed model results. Helper unit tests establish software behavior only. Use the [behavioral cases](cases.json) and [starter fixtures](README.md) inside an authorized nonlive evaluation. Do not purchase model runs or connect customer data just because these files exist.

## Compare against the old stack

Choose representative completed and stalled Veto tasks. Preserve the same starting code, sources, constraints, expected outcome, tool availability and allowed budget. Run the old and new editions separately; record actual model/version/settings and differences. Reset disposable state between attempts without resetting shared work. Use multiple trials when permitted to expose variability. Do not cherry-pick one good answer.

Keep a holdout set the builder does not use for tuning. Include sound candidates and correct founder suggestions, not only planted defects. Pair each claim about independence with a positive control: the agent must agree when agreement is supported, follow an informed permissible decision, and preserve an explicit taste constraint. Challenge quality is not an objection count.

## Establish the oracle independently

For deterministic behavior, use independently specified outcomes and controlled defects. For product judgment, have a qualified reviewer identify the user job, supported constraints, consequential findings and acceptable alternatives before reading the agent's verdict. Reserve professional domain conclusions for the appropriate expertise. Synthetic user reactions are not usability observations.

Hide source/author/status labels for comparative grading when practical; vary presentation order. Keep required constraints and safety information. Record the first verdict before showing founder annotations or builder rationale. Label already-exposed reviews as informed. A new session can reduce context anchoring; it does not make evidence independent or eliminate model bias.

## Judge the work, not the confidence

Assess: correct prioritization of the important bottleneck; evidence-backed findings; appropriate preservation of sound work; genuinely better alternatives; a useful falsifier; successful integrated repair; and truthful acceptance. Separately count false alarms, missed consequential defects, unauthorized changes, weakened assertions, unnecessary escalation, time, model/tool use and founder intervention.

A favorable overall score cannot compensate for a serious integrity violation. Record partial and blocked outcomes. Do not mark a model's unsupported explanation as proof merely because its wording matches the rubric. Test whether the next reviewer can reproduce the finding and whether the changed product solves it.

## Claim only the measured improvement

A useful first result is: “On these assignments with these tools, the new edition found these consequential issues and reduced this observed intervention, while preserving these controls.” A benchmark improvement is not field demand, universal superiority, or live release permission.

If outputs become longer but decisions or repairs do not improve, remove the added process. If the critic disputes correct decisions for sport, correct the false-positive incentive. If autonomous reviews fail because the reviewer cannot access the actual candidate, repair access or the evidence route rather than adding stronger personality instructions.

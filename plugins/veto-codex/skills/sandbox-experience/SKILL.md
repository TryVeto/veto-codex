# Sandbox experience

**Remove the danger, not the meaning.** Make a recognizable task, meaningful action, believable consequence and inspectable result possible without private founder coaching.

Read [sandbox and local practice](../../references/sandbox-and-local.md), [working boundaries](../../references/working-contract.md) and the relevant [Veto contract](../../references/veto-contract.md). Inspect the exact implementation, actual provider modes and runtime. Do not redesign unrelated product screens or build a general simulator.

Before the first browser navigation for local UI work, read installed local-development guidance, use the approved loopback-only HTTP preview serving the intended directory, and verify the target renders with one responsive control. Do not initiate file: navigation. Preserve any existing denial; an allowed origin is not permission to rehost blocked content. Diagnose the enforcing layer before proposing approval changes.

Choose the experiment: what should this evaluator learn and what can this rehearsal not prove? Preserve required identity/authority distinctions and the real same-job relationships. Define the ordinary sufficient path and one relevant variation; do not seed the action being tested as already complete.

At each input screen, provide scenario-valid synthetic values beside the task where needed, with explicit Copy or Fill controls when useful. Keep simulation controls separate from product controls. Do not infer real wire validity, use live contact details, or expose credentials. A functional Sandbox label stays; decorative eyebrows do not.

Role switching changes perspective, not submitted facts, approval, accepted responsibility or reset. Reset names the owned scope and preserves unrelated work. Disclose storage durability and any expiry; test the promised leave/reopen behavior on the actual route.

Classify capabilities as shared real implementation, simulated under a declared rule, represented only, or absent. A scripted response is not a live model result. A local success is not bank execution, external delivery, customer comprehension or demand. Keep fictional provenance inside exported results.

Enforce nonlive effects in actual server/adapters/permissions; a banner is insufficient. A failed test adapter never falls back to live services. No production credentials, unapproved sends, money movement, public tunnels or paid resource creation. Preserve the permitted browser and active pause; a missing browser gate stays unverified.

Verify entry, sample use, source inspection, correction, Help/Back, relevant keyboard/narrow states, saved result and next-role retrieval. Test a meaningful failure followed by allowed repair. Reconcile uncertain saves; recover a failed notice without repeating the saved act. Use the current components and lifecycle commands.

For handoff create [the review pack](../../references/review-pack.md) at the tested candidate. Return actual changes, supported simulation/persistence scope, checks performed and missing real-world proof. A clear rehearsal should make the evaluator competent to judge, including to reject the product—not merely impressed.

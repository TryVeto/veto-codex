# Integration design

Build the path through one office's existing work, not a logo collection. Read [working boundaries](../../references/working-contract.md) and [Veto's undertaking](../../references/veto-contract.md).

For WorkOS configuration/authentication work, use [the environment and admission contract](../../references/workos-environments.md) with the existing integration; do not restart vendor selection. An audit remains read-only. Setup, credentials, membership changes and release each require their actual authority.


## The installation and return are part of the product

Apply [Stripe-inspired whole-job ownership](../../references/stripe-operating-system.md): discoverability, setup, credentials, correct sample, errors, recovery and useful endpoint belong to the same delivery. Qualify one meaningful route instead of accumulating “connected” labels. Challenge a founder-suggested vendor when an existing permitted route serves the job better.

For a provider-dependent choice, keep source-published capability, actual implemented behavior, customer configuration and contracted permission separate. The supplied expanded integration skill is preserved as [source material](../../research/source-skills/veto-integrations.md); use it for a deeper route question, not automatic procurement or an expanded roadmap.

## Qualify the need first

Name the exact task the person must still carry without this connection or the fact/endpoint Veto cannot establish. Inspect current adapters, actual customer configuration and the competent manual or linked route. A secure upload may beat a new partnership; a repeated reconciliation burden may justify a deep connector. Do not migrate working infrastructure to make the stack look uniform.

Separate entry, evidence, participation, normal-file return and institutional execution/protection connections. An account observation is not payment authority. A working read is not permission to write. A vendor page is not Veto entitlement. A tool connection for the development agent is not an integration inside Veto's product.

The attached integration analysis proposes existing email and secure contribution links plus normal-file return; Outlook conditional on the office; one qualified account-evidence route; identity/telephone only where needed. It names RBJ, the exact product called Genie and ValidiFI as qualification candidates, not currently verified integrations. Recheck time-sensitive documentation and terms at the actual decision; do not promote this source snapshot into procurement authority.

## Define the complete contract

Use [the route contract](../../templates/integration-contract.md) only for unresolved fields. Require a permitted purpose, supported operations, constrained data/audience, source-of-truth mapping, named owner and recovery before scoring attractive benefits. Unknown rights can block live reliance without blocking an authorized isolated spike.

Preserve tenant and external-file identity independently of email subjects. Bind input, question, reply and issued record editions. Define what each acknowledgment proves: provider accepted, recipient server accepted, human contribution made, review saved, record placed, or bank event observed. Derive product statuses from these narrower facts.

Minimize access: a selected-message UI does not narrow a broad mailbox token. Qualify shared mailbox, delegated/application scopes, revocation, source independence, retention and vendor contractual conditions. Keep credentials out of prompts/logs/client code. Do not ask for bank passwords or codes.

## Make failure recoverable

Plan duplicate/out-of-order events, forged or stale callbacks, revocation, provider outage, file-map ambiguity, expired links and unknown outcomes. Use supported idempotency and destination reconciliation; local deduplication alone does not prove exactly-once external effect. Retry the same issued record, not an evolving regenerated document. Recover a notice without recommitting a decision.

A disconnected route stops new access and exposes its affected obligations with a real owner. Retention/deletion follows actual policy; neither discard accepted records nor retain everything forever by default. The fallback must function during the outage it addresses.

## Prove and select

In an authorized environment, test intake through usable return on the same job, plus the relevant failure-and-repair case. Label mocks, sandbox calls and actual external evidence separately. Product success is the office's supported endpoint with less total burden, not HTTP 200 or a green Connected badge.

Recommend the best route with its qualification gaps, installation/maintenance/support burden, owner and next decision. Treat sending, purchasing, changing scopes, installing an MCP server and production exposure as separate effects requiring actual authority. Do not install or expose them merely because this skill describes them.

## Conditional domain and channel guidance

Use [primitives](../../references/primitives.md) when linking jobs, source editions, decisions or delivery events. Use [financial phone experience](../../references/financial-phone-experience.md) only for a selected telephone intake/help route. Do not turn a new reference into permission for a provider purchase, dial, recording or broader collection. Source, published capability, contracted permission and observed endpoint remain separate.

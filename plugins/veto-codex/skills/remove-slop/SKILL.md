# Remove slop

Slop is apparent finish without enough judgment, coherence or care. Do not trade a generic dashboard for a generic “anti-AI” aesthetic. Read the [working contract](../../references/working-contract.md) and [Veto contract](../../references/veto-contract.md) as relevant.


## Walk the product before discussing it

Use [the review protocol](../../references/review-protocol.md). The task, fixed constraints and actual candidate come before the founder's preferred diagnosis or builder's explanation. A fresh review should find consequential friction without needing Sebastian to annotate each screen. Do not invent a minimum finding count.

Adopt [Stripe-inspired craft](../../references/stripe-operating-system.md), not Stripe's branding. After a supported correction, preserve one reusable regression or calibrated example where it will prevent recurrence. Do not add another sentence to every skill or let endless polish displace the accepted complete capability.

## Respect the requested mode

A review returns findings, not edits. A craft pass changes the named surface while preserving accepted structure, behavior, identity and copy outside scope. A visual-only pass preserves the words. An open redesign belongs in [product-design](../product-design/SKILL.md). Do not convert “make it better” into a new platform.

Inspect the exact candidate, source, content, existing tokens/components and rendered target. Reproduce interactions before describing them as broken. A screenshot supports visual findings, not saving, permissions or delivery. State missing access without inventing defects.

## Diagnose the kind of failure

Use the [calibration catalog](../../references/slop-catalog.md) when an example would change the judgment. Inspect six distinct failure types: surface, semantic, interaction, service, epistemic and organizational. Ask separately: does this deserve to exist, does it make sense as a whole, and is it made with care? No average score excuses a critical failure.

For each consequential issue record **observation → likely effect → hypothesis → correction → verification**. Name location/state, severity and certainty: observed, inferred or preference. Preserve strengths. “Feels AI” and “make premium” are not actionable findings.

## Subtract the right things

Remove decorative preheadings, repetitive summaries, empty reassurance, gratuitous metric cards, unnecessary launch choices and containers without a grouping purpose. **No decorative eyebrow, kicker or overline above a heading.** Keep actual form labels, breadcrumb context, material status and required disclosures. Judge function, not capitalization or class name.

Keep the decisive source beside the question. Preserve contrary material, original-source access, unresolved concerns, separate actors and useful repair. A cleaner screenshot that hides uncertainty or removes the only correction/help path fails.

Name the actual action and result. A saved receiving review is not a sent wire. A help note is not delivered assistance. A generated PDF is not filing. Do not “solve” a false claim by retaining the misleading headline and adding a buried disclaimer.

Use the existing type scale, aligned rows and coherent spacing. Remove repetition before shrinking type. Inspect wrapping, numerals, long names and readable metadata. Improve composition rather than adding a new theme or arbitrary style overrides. Motion must clarify or serve a deliberate purpose, not make repeat work wait.

## Repair and verify

For edits within scope, fix misleading claims, lost work, inaccessible behavior and blocked completion first; then major comprehension/hierarchy; then detailed visual finish. Report serious out-of-scope defects without silently broadening the patch. Batch related repairs and re-render the affected route after changes. Preserve valid assertions and approved baselines.

The optional [source scanner](../../scripts/lint_slop.py) finds suspicious literal patterns. Use `python3 -B <plugin>/scripts/lint_slop.py <actual-ui-path> --json`. It is read-only and heuristic; findings need semantic review and a clean run proves neither craft nor accessibility. The process exit code distinguishes findings, no findings and incomplete coverage; read the report.

Operate normal, long/dense, narrow, error, correction and completion states relevant to the change. Check keyboard, focus return, zoom and perceivable status. Confirm user-facing meaning survives subtraction. Inspect the images you produced. Missing rendered evidence remains missing.

Stop after the scoped acceptance is met. Return the changed artifact or prioritized critique, fresh checks, limits and one remaining action only when needed. Do not schedule another review cycle without an identified unresolved problem.

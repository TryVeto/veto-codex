# Build a capability

Make one important outcome work across its real boundaries. Read the [working contract](../../references/working-contract.md) and [Veto contract](../../references/veto-contract.md). Use the accepted mandate; do not rewrite the goal to match what is easy.


## Enter at the requested operation

For “start local dev,” use the [local-start fast path](../../references/sandbox-and-local.md#local-start-fast-path) and stop after the requested readiness check. Do not turn use into tooling repair, a product audit or a new framework. For implementation or CI repair, apply the [risk-weighted engineering floor](../../references/engineering-quality.md): use existing commands, preserve meaningful gates, and match tests to consequences rather than diff size.

## Make dependable speed a system property

Use [Stripe-inspired delivery](../../references/stripe-operating-system.md): first working join early, stable semantics, clear errors, usable examples and safe observable change. Own the complete capability across disciplines rather than waiting for a department to finish. When a risky change is necessary, separate compatibility/migration steps and verify the relevant transition; do not casually rewrite the product.

For UI work, read installed local-development guidance before the first browser navigation. Use the approved loopback HTTP preview; do not initiate file: navigation. Establish the rendered target and one interaction before substantial implementation. Use [local preflight](../../references/sandbox-and-local.md). A policy denial forbids rerouting the denied content; a failed origin does not prove every browser route unavailable. Resolve the server and actual build answering the allowed browser. Produce [an inspectable review pack](../../references/review-pack.md) for a substantial handoff without forking the app or making the founder capture it. A protocol is not permission to deploy or contact anyone.

## Establish the current mechanism

Inspect the repo instructions, dirty work, relevant source/tests, run commands, environment and canonical preview. For branch/worktree, commit or integration decisions use [Git handoff](../../references/git-workflow.md). For auth or environment-boundary changes use [WorkOS qualification](../../references/workos-environments.md); neither is a mandatory audit for unrelated work. Reproduce the affected path at the layer actually available. Historical observations and similarly named builds are not a current diagnosis. Trace the same file, request, instruction and actor from intake through contribution, review, help and destination.

Find the earliest consequential broken connection. Separate observation, hypothesis and diagnosis; use [exact-action diagnostics](../../references/diagnosis-and-approval.md) when a symptom is disputed or approval is ambiguous. Do not contradict a reported sign-out without checking the actual test session. Classify connection refusal separately from authentication and policy denial. Record candidate, origin, start command, storage and process ownership. Use separate data/ports for restart and fault tests; do not kill the review server or another worker's process. Do not promise persistent uptime the host cannot provide.

For a local-environment repair, use the same [local lifecycle](../../references/sandbox-and-local.md): inspect actual commands and toolchain, reproduce one meaningful journey, repair its demonstrated obstacle, and prove it can be recreated. Keep fast edit checks separate from packaged-runtime qualification; select the latter for runtime-sensitive changes or required handoff gates, not every cosmetic edit. Preserve the stable review instance while other workers edit or inject faults. Do not choose a package manager or CI path from a historical report alone.

## Frame and join early

For the selected change, establish the outcome, preserve/non-goals, shared state/command contract, actual permitted actions, expected ordinary result and meaningful refusal-and-repair. Reuse the [work order](../../templates/work-order.md) only where the existing record lacks detail.

Agree the interaction with the designer while frontend/backend make a first joined path. Work in isolated or explicitly partitioned change surfaces. The Head owns integration and resolves unowned dependencies. A component, endpoint or mocked screen is not the complete capability. Preserve a working local implementation rather than resetting to a simpler old export.

For a defect, isolate its cause and establish a discriminating regression before layering fixes. Test failure for the intended reason; repair the mechanism, not only the copy. A large bounded change is appropriate when needed. Do not optimize for a small diff at the expense of an incomplete promise.

## Preserve the domain at every join

Apply the relevant [One Real Wire contracts](../../references/one-real-wire.md), not every hypothetical future feature. Enforce actual permissions, tenant boundaries and current material basis in trusted software. Preserve original evidence, distinct concerns, private drafts, currentness and explicit personal acts. A disabled button or model answer is not an authority control.

Known save failure cannot produce durable success. For lost responses, reconcile the original operation rather than creating a new consequential act. Recover notice/delivery independently of commitment. Qualify change invalidation; do not erase justified work or inherit stale decisions. Data-shape changes need existing-record handling and recovery, not clearing storage to pass.

Sufficient cases stay quiet. Holds preserve their permitted remedy; pause/no-contact limits still apply. Returned replies keep their actual question edition. Help reaches the participant and resumes the same task. Issue one canonical record and establish the agreed destination. Local simulation is labeled and never credited as external delivery or staffed service.

## Verify and deliver the candidate

Run focused tests during iteration and integrated checks after freezing the candidate. Re-exercise actual UI save/reopen and relevant restart/role-switch/recovery. Changes to shared primitives need affected buyer-funding and adjacent-surface checks. Source/unit success does not replace a missing permitted-browser test.

Use [product-tests](../product-tests/SKILL.md) for final acceptance. Evidence identifies source plus dirty diff/build/configuration. Preserve failed attempts and unrun gates. Give the independent verifier the contract and candidate; self-review is not independent. Do not change a legitimate expectation just to pass.

For an authorized preview handoff, use [candidate-bound delivery](../../references/preview-and-release.md): distinguish the saved sandbox from the canonical app, qualify the exact hosted revision and finish the named journey. Never substitute the local SHA for unknown hosted identity. Branch publication, shared-preview promotion and production are separate actions. Deliver matching source, run instructions and observed evidence. Stop at the authorized endpoint; continue independent in-scope work while a dependency is blocked. Save the specific remaining action and resume state, not another polishing loop.

## Preserve domain meaning through the bounded bet

For schema, command or state changes, apply [the primitive distinctions](../../references/primitives.md) only to the affected boundary. A File may contain several accountable Jobs; source evidence, questions, obligations, decisions and result editions do not collapse into one approval flag. The model is not a naming migration or a screen catalog.

Use the current assignment revision. A new checkpoint does not waive parent acceptance. Handle changed direction with [work control](../work-control/SKILL.md), keeping compatible work and rechecking affected joins.

For agent-native delivery, use [investigation and repair](../../playbooks/investigate-and-build.md) and [application verification](../../references/application-verification.md). Reuse `verify-veto` in the product repository; do not create a second harness.

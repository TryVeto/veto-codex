# Veto working method

Merge this section into an existing repository entry point only during authorized
setup. Do not replace its charter or copy the whole handbook here.

For substantial authorized Veto work, load the installed Veto Codex entry skill
(`veto-codex`) and only the procedures relevant to the task. Use current repository
instructions and accepted company/product decisions as the governing context.
An installed plugin supplies methods, not additional authority.

Own context recovery, coordination, implementation, verification and resumable
handoff. Sebastian is not the message bus or default manual tester. Keep one
accountable execution owner and preserve useful domain-manager judgment.

Use the repository's maintained verification capability; in TryVeto/product this
is `.agents/skills/verify-veto/SKILL.md` and `docs/agent/FEATURE_MAP.md`. Self-tests do
not replace required independent acceptance. Ordinary Git work and environment
promotions remain subject to the repository's distinct authorization rules.

Keep task state outside plugin caches. Check the current native goal and latest
pause before continuing; a handoff record or plugin refresh cannot resume work.
Return Done / Exceptions / Next with actual artifact-bound evidence.
